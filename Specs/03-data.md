# Данные и модель хранения

## Доступность источников

В репозитории есть только исходный PDF кейса. CSV, исходные аналитические материалы, перечень разрешенных новостных источников и LLM-доступ не предоставлены. Ссылки «на данные» в PDF — указатели на внешний комплект, не сами данные. До получения использовать отдельно маркированные синтетические fixtures; не выдавать их за банковскую аналитику. Пока fixtures и ingestion не реализованы.

До просмотра файлов не предполагать separator, кодировку, представление bool, валюту/единицу выручки, кардинальность стран или отсутствие дублей. ID хранить строками, денежные суммы decimal/numeric, неизвестное значение — null, а не 0/false. ОКВЭД не преобразовывать в float.

### `df_Fid_Uid_link_hack.csv` — связи людей и компаний

`SYNTHETIC_F`, `CITY_NAME`, `RC_NAME`, `SYNTHETIC_U`. Использовать обезличенные связи для анализа групп; не считать эту таблицу учетными записями пользователей и не выводить автоматически роль/права человека из связи.

### `df_Uid_payment_hack.csv` — платежные связи

`BENEFICIARY`, `PAYER`, `PAY_AMT`, `PAY_CNT`. Направленное ребро payer → beneficiary, сумма и число платежей. Период, валюта, агрегация, наличие самоплатежей и направление рисков уточняются. Не выводить причинность или зависимость бизнеса только из суммы платежей.

## Будущие сущности PostgreSQL

| Сущность | Основные данные |
| --- | --- |
| companies / company_groups | synthetic ID, признаки, версия профиля, source reference |
| company_person_links / payment_edges | обезличенные связи и метаданные загрузки |
| users / memberships | отдельная модель пользователя, роли и разрешенные компании |
| source_documents / document_chunks | kind=news/bank, URI, время публикации/загрузки, hash, версия, текст, page/offset |
| events / event_documents | нормализованное событие, дедупликация и ссылки на документы |
| analysis_runs / run_steps / run_events | scope пользователя/компании, статус, версии, бюджет, tool calls, результаты шагов |
| insights / insight_claims / citations | факты, позиция банка, AI-выводы, confidence, источники и признаки |
| conversations / messages | вопросы и ответы с разрешенным контекстом |
| feedback | usefulness/error labels, пользователь, версия инсайта |
| outbox / idempotency_keys | надежная доставка jobs, повторяемые запросы |

Это логическая модель; `src/db/schema.ts` оставлен пустым. Таблицы/индексы/RLS/миграции появятся отдельно при реализации. Схемы обмена валидировать независимо от ответа LLM.

## Ingestion и retrieval

1. Сохранить immutable-оригинал, checksum, источник, права доступа, время загрузки и batch ID.
2. Проверить поля/типы и отправить ошибочные записи в quarantine с причиной, не теряя исходник.
3. Нормализовать документы; точные дубли по hash, смысловые — с сохранением всех source links.
4. Извлечь факты и сущности, сохранить интервалы цитат и даты; учитывать актуальность и противоречия.
5. Начать с PostgreSQL full-text/фильтров. Vector search/pgvector добавлять только после оценки качества и согласования допустимой embedding-модели; список LLM сам по себе не разрешает произвольный embedding API.
6. Хранить воспроизводимый snapshot: версия профиля, корпуса, алгоритма ранжирования, prompt/skills, model ID.

Секреты, полный чувствительный профиль и неотфильтрованный текст провайдера не попадают в trace. TTL/retention и права на хранение внешних текстов определить до реального ingestion.
