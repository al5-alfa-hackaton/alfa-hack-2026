# Подключение `@alfa/agent` к бэкенду

Состояние на 25.10.2026: все пункты 1–7 подключены в `projects/backend` и `projects/frontend`, включая ежедневное обновление новостей. Перед запуском бэкенда пакет агента собирается командой `pnpm --filter @alfa/agent build`: бэкенд берет его из `dist`.

Настройки бэкенда (`projects/backend/.env`):
- `RANKING_LIMIT=10`, `LLM_MAX_OUTPUT_TOKENS=10000` — агент разбирает 10 событий, в ленту идут все прошедшие проверку. `FEED_CARDS` не задан.
- `NEWS_REFRESH_CRON=0 9 * * *`, `NEWS_REFRESH_TZ=Europe/Moscow` — обновление новостей в 09:00 МСК. Без `NEWS_REFRESH_CRON` расписание снимается.
- `AGENT_VERIFY=false` — проверка выводов выключена: точность пока низкая (README пакета, «Оценка качества»). С `true` на запуск приходится до `AGENT_MAX_STEPS + 3` вызовов, и резерв проверяется под это число.
- `LLM_MAX_OUTPUT_TOKENS` не ставить 2000: по умолчанию 4000, при 2000 ответ обрезается.

Проверки:
- `pnpm --filter @alfa/backend test` — 48 тестов, включая перезагрузку новостей без перезапуска;
- интеграционные `RUN_INTEGRATION=true TEST_DATABASE_URL=… pnpm --filter @alfa/backend test:integration` — 17 тестов, число вызовов модели на запуск — 1;
- `pnpm --filter @alfa/frontend test`, `pnpm typecheck`.

## 7. Обновление данных по расписанию

- `pnpm news:refresh` выполняет `ingest --news`, затем `news:fulltext`, затем `news:tag` и в конце записывает `data/processed/news-refreshed.json`. Размечаются только новые новости и те, у которых появился полный текст. 25.10 за 2 мин 45 с добавилось 553 новости (1603 → 2156), разметка стоила 4,47 ₽. После смены `NEWS_TAG_PROMPT_VERSION` размечается весь корпус (~12 ₽ на 1600 новостей).
- В Coolify worker монтирует данные на запись, API — только на чтение. Расписание по умолчанию — `0 9 * * *`.
- Запуски, которые шли во время обновления и были прерваны, при возобновлении завершатся с `execution_context_changed` — их нужно запустить заново.
- Материалы банка и CSV компаний сами не обновляются: `unzip bank-ocr.zip` (архив передается отдельно), затем `pnpm --filter @alfa/agent ingest --bank` и перезапуск API и worker.
- `RUN_RESERVATION_RUB=25` исчерпывает дневной лимит 500 ₽ за 20 запусков, хотя сводка стоит около 0,5 ₽, а вопрос — около 0,25 ₽. Резерв достаточно держать на уровне `(AGENT_MAX_STEPS + 2) × LLM_GATEWAY_REQUEST_CAP_RUB`.

## Как проверить на сайте

1. `pnpm --filter @alfa/agent build`, перезапустить API и worker, открыть http://localhost:3000. Войти как `client_u_68157` (пароль — в `docs/dataset-accounts.md`) и нажать «Обновить сводку». Ожидается:
   - до 10 карточек (на 25.10 — 6), у каждой в «Почему для вас» не больше трех причин;
   - в `agent_model_calls` у запуска только ключи `agent:N`, без `structure`;
   - на 25.10 запуск занял около 30 с.
2. Открыть «Разобрать влияние». Ожидается:
   - заполнены «Риски» и «Возможные следующие шаги»;
   - во вкладке «Источники» новость подписана «Полный текст публикации»;
   - в конце текста нет «Подробнее — в материале…» и рекламы.
3. Во вкладке «Вопросы»:
   - «Расскажи кратко» — одно-два предложения;
   - «Привет!» — одна-две фразы без уточняющего вопроса;
   - «насколько вырастут наши расходы по кредитам?» — без выдуманных сумм, с уточнением;
   - следующий ответ пользователя «кредиты 3 млрд, ставка ключевая + 3%» — расчет без нового уточнения.
4. Войти как перевозчик `client_u_3263` и обновить сводку. Новости про БПЛА возможны только с прямой связью с перевозками, например потери портов от атак. Сводок о сбитых беспилотниках быть не должно.
5. Обновление новостей: в логе worker при старте нет ошибок, в Redis есть ключ `alfa:news-refresh:repeat:daily`. Ручной `pnpm news:refresh` заканчивается строкой «новостей было N, стало M», и через минуту в логах API и worker появляется `News corpus reloaded: M items`.
6. Пакетные проверки: `pnpm --filter @alfa/agent eval:ranking` (бесплатно) и `pnpm --filter @alfa/agent eval:answers` (~10 ₽). Ориентиры — последние отчеты в `packages/agent/results/`.
