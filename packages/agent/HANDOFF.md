# Интеграция `@alfa/agent` с бэкендом

Документ описывает, какие компоненты пакета `@alfa/agent` использует бэкенд (`projects/backend`) и фронтенд (`projects/frontend`), как они настраиваются и как проверяется их работа. Состояние на 25.10.2026.

Бэкенд импортирует пакет из `dist`, поэтому после изменения кода пакета его нужно пересобрать: `pnpm --filter @alfa/agent build`.

## Настройки

Переменные `projects/backend/.env` (в Coolify — переменные окружения ресурса, значения по умолчанию заданы в `compose.coolify.yaml`):

| Переменная              | Значение по умолчанию | Назначение                                                                                                                                                            |
| ----------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RANKING_LIMIT`         | 10                    | Число событий, которые разбирает агент                                                                                                                                |
| `FEED_CARDS`            | не задано             | Ограничение числа карточек в ленте; без значения показываются все прошедшие проверку                                                                                  |
| `LLM_MAX_OUTPUT_TOKENS` | 10000                 | Длина ответа модели. Значения ниже 4000 приводят к обрезанию ответа на 10 событий                                                                                     |
| `AGENT_VERIFY`          | `false`               | Проверка выводов моделью. Точность проверки пока недостаточна (README пакета, «Оценка качества»). При `true` на запуск резервируется до `AGENT_MAX_STEPS + 3` вызовов |
| `NEWS_REFRESH_CRON`     | `0 9 * * *`           | Расписание обновления новостей. Без значения расписание снимается                                                                                                     |
| `NEWS_REFRESH_TZ`       | `Europe/Moscow`       | Часовой пояс расписания                                                                                                                                               |

Резерв на запуск `RUN_RESERVATION_RUB` достаточно держать на уровне `(AGENT_MAX_STEPS + 2) × LLM_GATEWAY_REQUEST_CAP_RUB`. Значение 25 ₽ исчерпывает дневной лимит 500 ₽ за 20 запусков, хотя фактическая стоимость сводки — около 0,5 ₽, вопроса — около 0,25 ₽.

## Обновление данных

- `pnpm news:refresh` последовательно выполняет `ingest --news`, `news:fulltext` и `news:tag`, после чего записывает `data/processed/news-refreshed.json`. Размечаются только новые новости и новости, для которых получен полный текст. Пример: 25.10.2026 обновление заняло 2 мин 45 с, корпус вырос с 1603 до 2156 новостей, разметка стоила 4,47 ₽. При смене `NEWS_TAG_PROMPT_VERSION` размечается весь корпус (около 12 ₽ на 1600 новостей).
- В `compose.coolify.yaml` worker монтирует каталог данных на запись, API — только на чтение.
- Запуск анализа, прерванный во время обновления корпуса, при возобновлении завершается с кодом `execution_context_changed`; его нужно запустить повторно.
- Материалы банка и CSV компаний по расписанию не обновляются. Для обновления материалов банка: распаковать `bank-ocr.zip` (передается отдельно), выполнить `pnpm --filter @alfa/agent ingest --bank` и перезапустить API и worker.

## Проверка в интерфейсе

1. Собрать пакет (`pnpm --filter @alfa/agent build`), перезапустить API и worker, открыть http://localhost:3000, найти `U_68157`, выбрать профиль и нажать «Обновить сводку». Ожидаемый результат:
   - до 10 карточек, в блоке «Почему для вас» — не больше трех причин;
   - в таблице `agent_model_calls` у запуска только ключи `agent:N`, без `structure`;
   - время запуска — около 30 с.
2. Открыть «Разобрать влияние». Ожидаемый результат:
   - заполнены разделы «Риски» и «Возможные следующие шаги»;
   - во вкладке «Источники» новость подписана «Полный текст публикации»;
   - текст статьи не заканчивается ссылками на другие материалы и рекламой.
3. Во вкладке «Вопросы»:
   - «Расскажи кратко» — ответ из одного-двух предложений;
   - «Привет!» — одна-две фразы без уточняющего вопроса;
   - «насколько вырастут наши расходы по кредитам?» — ответ без вымышленных сумм, с уточняющим вопросом;
   - ответ пользователя «кредиты 3 млрд, ставка ключевая + 3%» — расчет без повторного уточнения.
4. Войти как перевозчик `client_u_3263` и обновить сводку. Новости об атаках БПЛА допустимы только при прямой связи с перевозками (например, повреждение портов); сводки о сбитых беспилотниках в ленту не попадают.
5. Обновление новостей: в журнале worker при запуске нет ошибок, в Redis есть ключ `alfa:news-refresh:repeat:daily`. Ручной запуск `pnpm news:refresh` завершается строкой «новостей было N, стало M»; в течение минуты в журналах API и worker появляется запись `News corpus reloaded: M items`.

## Не реализовано

- Показ других источников того же события (`relevance.relatedNewsIds`) в карточке.
- Регулярное обновление материалов банка и CSV компаний.
