# packages/agent

Исследовательский CLI-прототип. HTTP-интеграция с frontend еще не реализована; [аудит и план переноса в backend](../../specs/08-research-integration.md).
## Как устроено

```mermaid
flowchart LR
    START([Вопрос + companyId]) --> agent[agent<br/>модель с инструментами]
    agent -- "вызов инструментов,<br/>лимит не исчерпан" --> tools[tools<br/>выполнение + журнал]
    tools -- "результаты" --> agent
    agent -- "ответ текстом" --> answered[answered]
    agent -- "хочет инструменты,<br/>но 12 шагов или<br/>20 вызовов исчерпаны" --> limit[limit<br/>ответ без инструментов<br/>по собранным данным]
    answered --> END([Ответ + источники])
    limit --> END
```

Модель сама выбирает инструменты, результаты возвращаются ей. Лимиты: 12 шагов, 20 вызовов; при исчерпании модель отвечает по собранным данным.

Ответ — 60–150 слов: прямой вывод, 2–4 причины через механизм влияния на компанию, позиция Альфа-Банка с датой, конкретное действие и сноски на источники. Под ответом печатает, где открыть каждый источник: PDF и картинку страницы или ссылку на новость. Промпты — `src/agent/prompts.ts`. Компанию задаёт сервер (`configurable.companyId`), не модель. Каждый вызов инструмента журналируется.

| Инструмент | Что возвращает |
| --- | --- |
| `company_profile` | ОКВЭД, выручка, продукты Альфа-Банка, ВЭД, регион, пропуски |
| `company_group` | Группа компаний и связи через общих физлиц |
| `company_counterparties` | Поставщики и покупатели, концентрация, отрасли |
| `news_search` | Поиск по новостям из RSS |
| `bank_search` | Поиск по материалам банка, с датой и страницей |
| `document_read` | Текст новости или страницы материала банка |
| `evidence_verify` | Есть ли цитата дословно в документе |

ОКВЭД — Общероссийский классификатор видов экономической деятельности: код отрасли компании (например, 42.99 — строительство инженерных сооружений). ВЭД — внешнеэкономическая деятельность: экспорт и импорт; в данных — признак наличия записей в базе ФТС (Федеральной таможенной службы) и страны, без направления (экспорт или импорт неизвестно).

Откуда инструменты берут данные:

```mermaid
flowchart LR
    csv[(CSV кейса:<br/>компании, связи, платежи)] --> company[company_profile<br/>company_group<br/>company_counterparties]
    rss[RSS: ЦБ, Интерфакс, РБК,<br/>Коммерсантъ, ТАСС и др.] -- "pnpm ingest" --> news[(news.json)] --> ns[news_search<br/>document_read]
    pdf[PDF банка — сканы] -- "pnpm ingest" --> png[PNG страниц] -- "pnpm bank:ocr<br/>(Qwen3.6)" --> ocr[(OCR-текст)] -- "pnpm ingest --bank" --> chunks[(фрагменты<br/>с датой и страницей)] --> bs[bank_search<br/>document_read<br/>evidence_verify]
```

Код: `src/tools` — инструменты, `src/agent` — граф, промпты, разбор ответа и поиск источников, `src/news` — разметка и отбор новостей, `src/data` — загрузка данных, `src/search` — BM25, `src/cli` — скрипты.

## Разбор ответа агента

В режиме ленты агент пишет размеченный текст: блок на событие со строками «Тип», «Главное», «Факт», «Позиция банка», «Вывод», «Риск», «Возможность», «Стоит проверить», а в режиме вопроса — «Ответ». `parseFeedAnswer` (`src/agent/feed-parser.ts`) превращает его в JSON без вызова модели:

- факты и позиция банка — дословные цитаты, сверенные `evidenceVerify`; длиннее 300 символов — сокращаются по границе предложения;
- выводы с признаками компании и оговоркой — утверждения `ai_inference`; признаки вне списка убираются;
- `summary`, `kind`, `risks`, `opportunities`, `actions`, `answer` — отдельные поля карточки;
- события с пометкой «пропустить» и события не из выбранных сервером в результат не попадают.

Режим вопроса по карточке (`buildTaskPrompt({ mode: 'question', question, context, conversation })`): агент отвечает на конкретный вопрос строкой «Ответ» — форма и длина по вопросу («в N предложениях», «списком», «кратко», «что делать», «какие риски»), без повтора прошлых ответов. Если для ответа не хватает сведений о компании, агент дает то, что можно сказать сейчас, и задает вопрос в строке «Уточнение» — один раз за диалог (`clarificationAllowed`). Сведения, которые сообщил пользователь, используются как данные компании «по вашим данным»; денежные оценки — только из чисел источников и пользователя.

Признаки компании — единый список `FEATURE_IDS` с подписями `FEATURE_LABELS` (`src/features.ts`): отрасль, выручка, регион, кредиты, гарантии, лизинг, депозиты, зарплатный проект, факторинг, внешняя торговля, отрасли группы, поставщики, покупатели. Из него строится правило промпта, его проверяет разбор ответа, на него ссылаются причины отбора; тест сверяет, что подписи и промпт покрывают все ID.

`createFeedFinalizer` — готовая функция для опции `finalize` графа: возвращает JSON в формате `batchDraftSchema` бэкенда (лишние поля zod отбросит), а если в ответе нет ни одного блока — вызывает переданный запасной `finalize`. Проверено на ответах 17 живых запусков: все разобранные утверждения прошли `gateDraft` бэкенда.

## Отбор новостей

Два шага:

1. **Разметка** (`pnpm news:tag`, `src/news/tagging.ts`). Модель (`LLM_MODEL_TAGGER`, по умолчанию DeepSeek-V4.1-Flash) пачками по 20 новостей проставляет: группы ОКВЭД вида `46.7` (словарь строится из данных компаний), темы (`key_rate`, `credit`, `fx`, `trade`, `commodities`, `demand`, `labor`, `regulation`, `inflation`), масштаб (`macro`, `sector`, `company`, `other`) и важность 0–3. Ответ проверяется zod, результат кэшируется в `data/processed/news-tags.json`; повторный запуск размечает только новые новости, смена `NEWS_TAG_PROMPT_VERSION` — весь корпус. 1019 новостей ≈ 4,4 ₽.
2. **Отбор** (`rankNewsForCompany`, `src/news/ranking.ts`). Связи компании: своя группа ОКВЭД (0,7; совпадение только по разделу — 0,4), отрасли группы и надёжные отрасли контрагентов с долей от 10%, продукты банка ↔ темы ставки и заимствований, ВЭД ↔ курс и торговля, зарплатный проект ↔ рынок труда. Темы учитываются только для новостей всей экономики или отраслей, связанных с компанией. Вклады объединяются как 1 − ∏(1 − вес), поэтому балл не упирается в 1.

```text
score = 0,65 × companyFit × важность + 0,15 × ракурс + 0,15 × свежесть + 0,05 × источник
важность: 1 → 0,5; 2 → 0,8; 3 → 1      ракурс: CFO — ставка, кредит, курс, инфляция; CEO — спрос, торговля, сырьё, труд, регулирование
свежесть = exp(−возраст / 14 дней), старше 90 дней — исключается
```

Новости «не про бизнес» и с важностью 0 не участвуют; из почти одинаковых заголовков остается более свежий. Результат совместим с `RankedNews` бэкенда. Причины — ID признаков из `FEATURE_IDS`, не больше трех, по убыванию веса: в карточке «Почему для вас» остаются только главные связи.

Ограничения: веса подобраны вручную на 6 компаниях; группа ОКВЭД 46.7 объединяет топливо и стройматериалы, поэтому топливному оптовику может попасть новость о жилищном строительстве.

## Полные тексты новостей

RSS дает у большинства источников только заголовок и лид. `pnpm news:fulltext` (`src/news/fulltext.ts`) скачивает страницу статьи и вынимает текст: сначала `articleBody` из JSON-LD, иначе абзацы и текстовые блоки самой длинной `<article>`; служебные строки («подписывайтесь», «читайте также», реклама, cookie) и строки короче 40 символов отбрасываются. Скачиваются только https-страницы доменов из списка источников, не больше трех переадресаций и 3 МБ, по три запроса параллельно с паузой. Обновленная новость получает `textSource: 'article'`, ее разметка сбрасывается и пересчитывается при следующем `news:tag`.

На 23.10: полный текст у 1718 из 2001 новости. Медиана длины текста: РИА 0 → 943 символа, Ведомости 0 → 1304, Коммерсантъ 219 → 972, события ЦБ 0 → 974. ТАСС отвечает 403 — остается лид; у РБК полный текст уже в RSS.

## Оценка качества

Две проверки, отчеты — в `results/`.

**Отбор событий** (`pnpm eval:ranking`, бесплатно). Два набора на дату 23.10.2026:
- `eval/ranking-set.json` — 6 компаний (опт, инженерная стройка, розница одежды, топливо, жилое строительство, грузоперевозки), 76 пар «компания — новость»; на них подбирались веса отбора;
- `eval/ranking-holdout.json` — отложенная проверка: 6 компаний из отраслей, которые при настройке не использовались (овощи, сыр, металлопрофиль, приборы, софт, гостиница), 83 пары.

В пул каждой компании вошли топ-5 правил по словам и ML-отбора для CFO и CEO. Оценки: 2 — прямо влияет на деньги компании, 1 — косвенно, 0 — не связано. Для каждой новости отмечено, какому руководителю она важна напрямую (ставка, курс, кредит — CFO; спрос, отрасль, регулирование — CEO); для другой роли оценка снижается на 1. Разметку сделал ассистент по профилю компании и тексту новости, ее нужно выборочно проверить экспертом. Корпус покрывает в основном 19–23 октября, поэтому отложены компании, а не период.

| Метрика | Почему она |
| --- | --- |
| P@3 (оценка ≥ 1) | пользователь видит три карточки — сколько из них про его компанию |
| P@3 строгая (оценка 2) | доля новостей, прямо влияющих на деньги |
| R@5 | доля связанных новостей пула, попавших в топ-5; полнота относительно пула, не всего корпуса |
| nDCG@5 | прямые новости должны стоять выше косвенных |
| Нерелевантных в топ-3 | то, что пользователь назовет мусором |
| Совпадение топ-3 с другими компаниями | персонализация; не зависит от разметки |
| Всё то же по ролям CFO и CEO | новость про ставку важна финансовому директору, про спрос — генеральному |

| Набор | Отбор | P@3 | P@3 строгая | R@5 | nDCG@5 | Нерелевантных в топ-3 | Совпадение с другими |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Настройка | Правила по словам | 53% | 8% | 40% | 0,44 | 47% | 61% |
| Настройка | ML-отбор | 69% | 19% | 49% | 0,63 | 31% | 50% |
| Отложенная | Правила по словам | 44% | 6% | 31% | 0,34 | 56% | 69% |
| Отложенная | ML-отбор | 69% | 25% | 61% | 0,72 | 31% | 22% |

На отложенных компаниях ML-отбор не хуже, чем на компаниях настройки, — признаков подгонки нет. Слабое место — роль CFO: P@3 у ML 56% против 83% у CEO. В топ финансовому директору попадают отраслевые новости, а не новости о ставке и кредите.

**Ответы агента** (`pnpm eval:answers`, около 8 ₽). Лента для тех же 6 компаний и 8 вопросов из `eval/questions.json` по первой карточке двух компаний. Ответ разбирается `createFeedFinalizer`, как в сервисе.

| Метрика | Почему она |
| --- | --- |
| Карточек опубликовано | сколько отобранных событий дошло до пользователя; пропуск агентом считается отдельно |
| Точность цитат | факт показывается только с дословной цитатой — доля цитат, найденных в документе |
| Заполненность карточки | есть главное, риск или возможность и шаг |
| Неизвестные признаки | ссылки на признаки не из `FEATURE_IDS` |
| Числа без источника | числа в выводах и ответах, которых нет ни в новостях, ни в ответах инструментов, ни в сообщениях пользователя — кандидаты на выдумку |
| Форма ответа на вопрос | «в 3 предложениях», «списком», «кратко», приветствие, уточнение при нехватке данных, без повторного уточнения после ответа пользователя |
| Повтор между ответами | сходство слов в ответах на разные вопросы по одной карточке |
| Время и стоимость | на запуск ленты и на вопрос |

Прогон 23.10 (DeepSeek-V4.1-Flash, промпт `stage1-2026-10-23.8`, 7,31 ₽; лента — 6 компаний настройки и 3 отложенные: металлопрофиль, софт, гостиница):

| Метрика | Настройка | Отложенная |
| --- | --- | --- |
| Опубликовано карточек | 18 из 18 | 9 из 9 |
| Точность цитат | 100% | 100% |
| Заполненность карточки | 83% | 78% |
| Числа без источника | 0 | 0 |
| Вывод ИИ выдан за позицию банка | 0 | 0 |

Карточек с проверенной цитатой материала банка — 100%. Форма ответа — 13 из 16 (на промпте `.7` было 11): «в 3 предложениях» и «списком» проходят. Не проходят «кратко» у U_57706 (68 слов вместо ≤ 45) и «привет» у обеих компаний — к приветствию агент добавляет уточняющий вопрос о выручке и кредитах. Повтор между ответами — 0,23. Лента — 25 с и 0,44 ₽, вопрос — 14 с и 0,22 ₽. Черновики ответов сохраняются вне git в `data/processed/runs/eval-answers-<дата>/`.

Новая метрика «Вывод ИИ выдан за позицию банка» ищет в выводах ссылки на оценку Альфа-Банка («Альфа-Банк ожидает…», «по прогнозу Альфа-Банка») и считает ошибкой, если у события нет дословной цитаты материала банка или позиция банка ссылается не на материал банка.

Процесс регулярного мониторинга — что смотрим при каждом изменении, ежедневно, еженедельно и ежемесячно, цели и обратная связь пользователей и экспертов — в [`docs/quality-monitoring.md`](../../docs/quality-monitoring.md). Ежедневный отчет по журналам сервиса (запуски, ошибки, время p50/p95, очередь, траты, доля ответов «недостаточно данных», оценки и комментарии пользователей): `pnpm monitor:report [ГГГГ-ММ-ДД]` из корня репозитория.

Метрики — `src/eval/metrics.ts`, тесты — `test/eval-metrics.test.ts`.

## Запуск

**при первой настройке**:

```sh
pnpm install
cp .env.example .env         # вписать LLM_BASE_URL и LLM_API_KEY; ID моделей уже подставлены
pnpm ingest                  # скачивает новости (RSS), вынимает из PDF картинки страниц
pnpm bank:ocr                # распознаёт картинки в текст: ~8 ₽, ~20 мин, повторный запуск продолжает с места обрыва
pnpm ingest --bank           # режет распознанный текст на фрагменты для поиска
pnpm news:fulltext           # полные тексты статей со страниц источников; бесплатно, ~10 мин
pnpm news:tag                # размечает новости для отбора: ~14 ₽ на 2001 новость с полными текстами, лимит --max-rub=10
```

**время от времени:**

```sh
pnpm news:refresh                     # свежие новости, их полные тексты и разметка: обрабатываются только новые
pnpm bank:ocr && pnpm ingest --bank   # только если появились новые PDF банка
```

**задать вопрос агенту:**

```sh
pnpm agent <companyId> "<вопрос>" [modelId]   # 0,2–0,5 ₽;
```

**проверки:**

```sh
pnpm test                                        # после изменений в коде;
pnpm tools:demo [companyId] [запрос]             # что видят инструменты;
pnpm llm:smoke <modelId> ...                     # отвечает ли модель, вызывает ли инструменты, держит ли JSON
pnpm ocr:compare <docId>/p01.png <modelId> ...   # сравнить OCR на одной странице; ~0,15 ₽ за модель
pnpm agent:compare <modelId> ...                 # сравнить модели агента на 5 вопросах; ~4–5 ₽
pnpm news:rank [дата|-] [companyId ...]          # топ-3 отбора новостей для CFO и CEO; бесплатно
pnpm eval:ranking                                # отбор: ML против правил на размеченном наборе; бесплатно
pnpm eval:answers                                # ответы агента: лента и вопросы; ~8 ₽
```

Результаты проверок — в `results/`. Ответы агента — в `data/processed/runs/`, вне git: в них цитаты материалов банка.

| Модель (ID) | Роль | Сильные стороны | Слабые стороны |
| --- | --- | --- | --- |
| DeepSeek-V4.1-Flash (`deepseek/deepseek-v4.1-flash`) | **Агент** | Сам завершает работу; вызывает несколько инструментов за шаг; использует контрагентов и группу компании; берёт свежий прогноз банка и отмечает, что он менялся; цитаты совпадают с текстом; дешевле Qwen на агентных прогонах | В OCR исказил число на графике (0,09 вместо −0,07); иногда приводит общую причину без опоры на данные |
