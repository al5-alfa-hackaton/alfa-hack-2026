# Упрощённая архитектура клиента

Архитектура основана на FSD, но использует меньше слоёв и разрешает практичные кросс-импорты.

## Слои

Зависимости направлены сверху вниз:

```text
app → pages → blocks → components → entities → shared
```

Нижний слой не должен импортировать верхний.

## `app`

Инициализация приложения:

- точки входа;
- роутинг;
- провайдеры;
- глобальный store;
- глобальные стили.

Бизнес-логику здесь не размещаем.

## `pages`

Компоненты, соответствующие маршрутам.

Страница:

- получает параметры маршрута;
- собирает экран из блоков;
- управляет состоянием, относящимся ко всему экрану.

Код, который используется только на одной странице, можно хранить рядом с ней. Не нужно заранее выносить его в отдельный слой.

```text
pages/room/
├── room-page.tsx
├── room-page.module.scss
└── use-room-page.ts
```

Страницы не импортируют другие страницы.

## `blocks`

Законченные части интерфейса, которые работают с бизнес-данными:

- таблица номеров;
- форма добавления устройства;
- информация об отеле;
- выбор организации.

Блок может содержать запросы, состояние, обработчики и модальные окна.

```text
blocks/rooms-table/
├── api/
├── model/
├── ui/
└── index.ts
```

Кросс-импорты между блоками допустимы, если они не создают цикл. Если два блока постоянно зависят друг от друга, их следует объединить.

## `components`

Переиспользуемые компоненты без бизнес-логики:

- таблицы;
- поля ввода;
- layout;
- заглушки;
- отображение статуса.

Компонент получает данные и обработчики через props. Он не выполняет бизнес-запросы и не знает о Redux или предметных сценариях.

Допустимы термины интерфейса: `Status`, `Header`, `Table`. Недопустимы знания о конкретном отеле, номере или устройстве.

## `entities`

Описание бизнес-сущностей:

```text
entities/room/
├── api.ts
├── types.ts
├── selectors.ts
├── lib/
└── index.ts
```

Здесь размещаются:

- типы;
- API сущности;
- селекторы;
- преобразования данных;
- простые проверки бизнес-состояния.

Сценарии пользователя и крупные React-компоненты здесь не размещаются. Например, `canResetRoom()` относится к `entities/room`, а форма сброса номера — к `blocks/reset-room`.

Кросс-импорты между сущностями допустимы, но циклические зависимости запрещены.

## `shared`

Технический код, не содержащий знаний о бизнесе:

- базовый HTTP-клиент;
- общие хуки;
- универсальные утилиты;
- глобальные типы;
- константы окружения.

Код про номер, устройство, организацию или отель не является `shared`.

## Куда положить новый код

Используйте первый подходящий вариант:

1. Настраивает приложение — `app`.
2. Является маршрутом или используется только одним маршрутом — `pages`.
3. Реализует законченную работу с бизнес-данными — `blocks`.
4. Только отображает переданные данные — `components`.
5. Описывает бизнес-сущность или преобразует её данные — `entities`.
6. Не знает о предметной области — `shared`.

Если место всё ещё неочевидно, положите код рядом со страницей. Выносите его ниже только после появления повторного использования.

## Именование

Файлы и директории называются в kebab-case:

- `rooms-table.tsx`;
- `use-room-filters.ts`;
- `room-api.ts`;
- `rooms-table.module.scss`.

React-компоненты называются в PascalCase, функции и хуки — в camelCase.

`index.ts` используется только как публичный API директории. Импорты внутренних файлов другого модуля запрещены.
