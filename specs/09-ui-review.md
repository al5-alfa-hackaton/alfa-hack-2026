# Frontend: дизайн-решения и проверка

## Контекст

Исходная ветка: codex/mock-app-cycle, 44dcfa1. Сохранены шесть синтетических событий, две компании, два аналитических ракурса и полный демонстрационный цикл. Перед изменениями проанализирован код, а не выдуман новый продукт.

Применены [Taste Skill](https://github.com/Leonxlnx/taste-skill/tree/main/skills/taste-skill) (6010f91) и [Better Web UI](https://github.com/aladicf/better-web-ui) (af21dcf): app-screen workflow, component strategy, anti-slop, hierarchy, critique и accessibility. Навыки использовались как руководство, их библиотеки не скопированы в продукт. Постоянный контекст — [.better-web-ui.md](../.better-web-ui.md).

Taste draw: **framed-sheet**, seed **2099893729**. Выбор: долгие сессии чтения и сравнения данных требуют спокойной рамки, одного рабочего полотна и сдержанного chrome. Сохранен красный акцент бренда, прежний Arial заменен self-hosted Manrope с кириллицей для различимой, но практичной типографики. Не добавлялись декоративные графики, метрики и фотографии без смысла.

## Основной вопрос экрана

- Лента: какое событие важно именно моей компании и почему?
- Разбор: какое влияние подтверждают источники и что проверить дальше?
- Источники: на что опирается конкретный вывод?
- Диалог: как уточнить влияние в сохраненном контексте?
- Контекст: какие признаки используются и чего не хватает?
- История: чем закончился мой запуск?

Собственный элемент продукта — связка «событие → почему для вас → признак компании». Она присутствует в ленте и разборе, а не спрятана за общей AI-плашкой.

## Что изменено

| Проблема исходника                                         | Решение                                                                                 |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Большой app.tsx со смешанными обязанностями                | Слои app/pages/blocks/components/entities/shared и проверяемые import boundaries        |
| Вступительный маркетинговый экран перед полезным действием | Прямой вход в сводку с видимым контекстом и выбором компании/роли                       |

| Фиолетовые и неоновые панели конкурируют с содержанием     | Нейтральные поверхности, красное действие, спокойные семантические статусы              |
| Навигация как локальный view state                         | Реальные routes, deep link reader, reload/back и восстановление фокуса                  |

| Плотный экран теряет контекст на телефоне                  | Компания в верхней панели, foldable Sidebar, доступные фильтры и проверка переполнения  |

## Самопроверка дизайна

После реальных снимков исправлены обрезанное название компании в switcher, слишком мелкие метаданные (подняты до 13px) и ширина фильтров на телефоне. Reader снят после завершения анимации, а не на пустом первом кадре.

Качественная оценка текущего интерфейса, не автоматическая сертификация:

| Эвристика                       | Балл 0–4  | Основание / предел                                                       |
| ------------------------------- | --------- | ------------------------------------------------------------------------ |
| Видимость состояния             | 3         | Фазы, отмена и история; пока симуляция, без реального SSE                |
| Соответствие предметной области | 3         | Влияние, признаки, источники и пробелы разделены                         |
| Контроль пользователя           | 3         | Отмена, выход из reader, back и явный retry                              |
| Последовательность              | 3         | Единые shadcn-примитивы и токены                                         |
| Предотвращение ошибок           | 3         | Scope, схемы хранилища, bounds вопросов; серверных прав пока нет         |
| Узнавание вместо запоминания    | 3         | Компания/роль и основание всегда доступны                                |
| Эффективность                   | 3         | Прямой вход, Cmd/Ctrl+K, сохранение и фильтрованный экспорт              |
| Минимализм                      | 3         | Удалены декоративные KPI/баннеры; длинные объяснения остаются по делу    |
| Восстановление                  | 3         | Empty/error/partial, retry и corrupted storage; live reconnect предстоит |
| Помощь                          | 3         | Честная маркировка demo, сценарии, источники и README                    |
| Всего                           | **30/40** | Рабочий demo UI; не production-ready банковский сервис                   |

Анти-паттерны: устранены градиенты/неоновые акценты, карточка на каждую цифру, generic hero и декоративные пиктограммы. Сам по себе «плоский» интерфейс не является доказательством качества: важны реальные действия и происхождение информации.

## Проверки

- TypeScript и architecture check: направления слоев, public APIs, отсутствие runtime-циклов. Type-only registration TanStack исключен из runtime graph.
- Unit: ranking, role/scope, честные ограничения ответа, run transitions/cancellation.
- Playwright: поиск/фильтры, persistence и изоляция, deep links/reload/focus, chat/feedback, отмена/история, partial/empty/error/budget/denied, export и mobile.
- Axe: основной экран light/dark, reader sources и conversation — WCAG 2 A/AA checks. Ручной keyboard/visual pass дополнительно; автоматизация не проверяет всю доступность.
- Taste inspector: реальные viewport 1440×900, 768×1024, 390×844. Первое измерение: 0 FAIL, замечание о доле мелких метаданных; после него текст метаданных увеличен. **Повторная проверка после исправления: 0 FAIL, 0 WARN.**
- Source lint: 0 FAIL. Шаблонный lint отмечает shadow declarations (включая `none` и inset underline), mono для буквального run ID и тире в текстах; это не decorative card shadows/типографический акцент на метриках.

Остаются осознанные ограничения: синтетические данные, сценарные ответы, локальное хранение, Chromium как тестовый браузер, server integration/auth/offline/SSE не реализованы. У chat scroll-region фиксированная высота, чтобы composer не прыгал при приходе ответа; свободное место в коротком диалоге — рабочая область, не декоративная карточка.
