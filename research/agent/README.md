# Research: агентная среда на LangGraph.js и набор инструментов

Этап 1 ML-части: агентская среда, подключение разрешённых LLM и набор инструментов. Собственный граф агента на LangGraph.js и типизированные read-only инструменты над данными кейса. Модели подключаются через OpenAI-совместимый API организаторов. Это не продуктовый код: после проверки инструменты и граф переносятся в backend worker (см. [specs/04-agent-runtime.md](../../specs/04-agent-runtime.md)).


LangGraph используется как библиотека оркестрации. Граф, узлы, инструменты и промпты написаны нами. Готовый автономный агент не используется (PDF, с. 18).

## Граф

```text
START → agent ──(модель вызвала инструменты, лимит не исчерпан)──→ tools ──→ agent
          ├──(модель ответила текстом)──→ answered → END
          └──(исчерпан лимит шагов или вызовов)──→ limit → END
```

Цикл ReAct: модель сама выбирает инструменты, результаты возвращаются ей в историю, ответ — текст со ссылками на источники. Структурированный JSON-инсайт и автоматическая самопроверка относятся к следующим этапам.

Scope компании задаётся сервером через `configurable.companyId`, модель не может его переопределить. Каждый вызов инструмента пишется в audit trail: аргументы, длительность, успех, размер ответа.

## Инструменты

| Tool | Что возвращает | Данные |
| --- | --- | --- |
| `company_profile` | ОКВЭД, выручка и масштаб, продукты Альфа-Банка, ВЭД и страны, регион, пропуски | `df_Uid_data_hack.csv` |
| `company_group` | Группа (GROUP_ID): размер, выручка, отрасли; компании через общих физлиц | + `df_Fid_Uid_link_hack.csv` |
| `company_counterparties` | Поставщики и покупатели, концентрация top1/top5, отрасли по объёму, самоплатежи | `df_Uid_payment_hack.csv` |
| `news_search` | BM25 по новостям из RSS с фильтрами по дате и источнику | `data/processed/news.json` |
| `bank_search` | BM25 по фрагментам аналитики банка, со страницей | `data/processed/bank-chunks.json` |
| `document_read` | Фрагмент новости или страницы материала банка | |
| `evidence_verify` | Есть ли цитата дословно в документе | |

Реализации в `src/tools/functions.ts` не зависят от LangChain, обёртки лежат в `src/tools/index.ts`. Все промпты и их версия — в `src/agent/prompts.ts`.

## Запуск

Из `research/agent` (данные кейса в `<repo>/data/raw`, в git не попадают):

```sh
pnpm install                 # из корня репозитория
cp .env.example .env         # заполнить LLM_BASE_URL, LLM_API_KEY, ID моделей
pnpm ingest                  # RSS → data/processed/news.json; страницы PDF → PNG
pnpm tools:demo [U_id] [запрос]   # все инструменты на реальных данных, без LLM
pnpm test                    # тесты на синтетических фикстурах, включая цикл агента на скриптовой модели
```

С доступом к API:

```sh
pnpm llm:smoke <modelId> ...       # ответ / tool calling / JSON + latency и токены → results/
pnpm ocr:compare <docId>/p01.png <modelId> ...  # сравнение моделей OCR на одной странице → results/
pnpm bank:ocr && pnpm ingest --bank  # OCR всех страниц банка (один раз, постранично кэшируется, можно продолжить после обрыва)
pnpm agent U_9250 "Как сохранение ключевой ставки 14% влияет на компанию?" [modelId]
```

## Модели

ID моделей берутся из `GET /models` шлюза организаторов. Используются только модели из списка кейса (PDF, с. 18):

| Модель в кейсе | ID в API | Роль у нас | Основание |
| --- | --- | --- | --- |
| DeepSeek-V4.1-Flash | `deepseek/deepseek-v4.1-flash` | Агент (`LLM_MODEL_AGENT`) | Сам завершает работу, использует больше данных о компании, дешевле Qwen. Проверено на 1 вопросе — предварительно |
| Qwen3.6 35B A3B | `qwen/qwen3.6-35b-a3b` | OCR сканов банка (`LLM_MODEL_VISION`) | Без ошибок в числах на 4 страницах ([сводка](results/ocr-compare-2026-10-21/SUMMARY.md)) |
| Qwen3-VL-30B-A3B-Instruct | `qwen/qwen3-vl-30b-a3b-instruct` | Не используется | Худший OCR: потерянные знаки, перепутанный порядок значений, выдуманный текст |
| Gemma 4 26B A4B | `google/gemma-4-26b-a4b-it` | — | Не проверялась |
| GLM-5.3-Flash | `z-ai/glm-5.3-flash` | — | Не проверялась |
| Kimi-K2.6 | `moonshotai/kimi-k2.6` | — | Не проверялась |

Шлюз также отдаёт `deepseek-cost-test`. Её нет в списке кейса, она не используется.

**Скрытые рассуждения выключены** (`LLM_REASONING_EFFORT=none`). Qwen3.6 и DeepSeek по умолчанию «думают» перед ответом: при лимите 2000 токенов рассуждения съедают весь лимит, ответ пустой, а вызов дороже в 200–300 раз. Шлюз понимает только `reasoning_effort`; `chat_template_kwargs.enable_thinking` игнорируется.

**Стоимость** каждого вызова шлюз возвращает в `usage.cost`; она выводится в `llm:smoke`, `ocr:compare`, `bank:ocr` и сохраняется в прогонах агента. Ориентиры: короткий вызов ~0,001; страница OCR на Qwen3.6 ~0,1–0,2; прогон агента ~0,3–0,5.

## Что выяснилось о данных

- **PDF банка — сканы.** Каждая страница представляет собой одну картинку, текстового слоя нет (64 страницы). Текст получается OCR на Qwen3.6 и кэшируется в `data/processed/bank-ocr/`. Из графиков извлекаются только подписанные значения, оси и легенды.
- Среди PDF есть `ALFA_Russian_Steels_1К21…15Apr2021`, отчёт 2021 года по стали. В списке материалов из PDF кейса его нет, а «Commodities performance» отсутствует.
- Компании: 85 525 строк, но только 85 514 уникальных ID. `U_428697` встречается 12 раз с разными профилями. ОКВЭД записан неоднородно (`41.2` и `41.20`).
- Выручка от 1 000 до 1,06·10¹¹, единица не указана. При допущении «рубли» порогу кейса (> 15 млрд) соответствуют только **115 компаний**.
- `AMOUNT_WORKERS_SPARK_GRADATION` почти пуст (заполнено 168 из 85 525). `ECO_MARK_LABEL` пуст у 4 157 компаний.
- Платежи: 1,38 млн рёбер, **встречаются самоплатежи** (payer = beneficiary), они исключаются из контрагентов. У крупных компаний большая доля объёма платежей приходится на контрагентов без профиля в CSV (у U_9250 это 81% по поставщикам).
- Продуктовые флаги отражают только отношения с Альфа-Банком, кредиты в других банках неизвестны.

## Новостные источники

Открытые RSS из allowlist в `src/data/news.ts`: Банк России (события, пресс-релизы), Интерфакс, РБК, Коммерсантъ, ТАСС, Ведомости, РИА Новости, Банки.ру. Переходы проверяются по allowlist на каждом редиректе. Дедупликация идёт по URL и нормализованному заголовку. RSS содержит в основном лиды, полный текст есть только у РБК.
