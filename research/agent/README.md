# research/agent

Исследовательский CLI-прототип. HTTP-интеграция с frontend еще не реализована; [аудит и план переноса в backend](../../specs/08-research-integration.md).
## Как устроено

```mermaid
flowchart LR
    START([Вопрос + companyId]) --> agent[agent<br/>модель с инструментами]
    agent -- "вызов инструментов,<br/>лимит не исчерпан" --> tools[tools<br/>выполнение + журнал]
    tools -- "результаты" --> agent
    agent -- "ответ текстом" --> answered[answered]
    agent -- "хочет инструменты,<br/>но 12 шагов или<br/>20 вызовов исчерпаны" --> limit[limit<br/>ответ без инструментов<br/>по собранным данным]
    answered --> END([Ответ + источники])
    limit --> END
```

Модель сама выбирает инструменты, результаты возвращаются ей. Лимиты: 12 шагов, 20 вызовов; при исчерпании модель отвечает по собранным данным.

Ответ — 60–150 слов: прямой вывод, 2–4 причины через механизм влияния на компанию, позиция Альфа-Банка с датой, конкретное действие и сноски на источники. Под ответом печатает, где открыть каждый источник: PDF и картинку страницы или ссылку на новость. Промпты — `src/agent/prompts.ts`. Компанию задаёт сервер (`configurable.companyId`), не модель. Каждый вызов инструмента журналируется.

| Инструмент | Что возвращает |
| --- | --- |
| `company_profile` | ОКВЭД, выручка, продукты Альфа-Банка, ВЭД, регион, пропуски |
| `company_group` | Группа компаний и связи через общих физлиц |
| `company_counterparties` | Поставщики и покупатели, концентрация, отрасли |
| `news_search` | Поиск по новостям из RSS |
| `bank_search` | Поиск по материалам банка, с датой и страницей |
| `document_read` | Текст новости или страницы материала банка |
| `evidence_verify` | Есть ли цитата дословно в документе |

ОКВЭД — Общероссийский классификатор видов экономической деятельности: код отрасли компании (например, 42.99 — строительство инженерных сооружений). ВЭД — внешнеэкономическая деятельность: экспорт и импорт; в данных — признак наличия записей в базе ФТС (Федеральной таможенной службы) и страны, без направления (экспорт или импорт неизвестно).

Откуда инструменты берут данные:

```mermaid
flowchart LR
    csv[(CSV кейса:<br/>компании, связи, платежи)] --> company[company_profile<br/>company_group<br/>company_counterparties]
    rss[RSS: ЦБ, Интерфакс, РБК,<br/>Коммерсантъ, ТАСС и др.] -- "pnpm ingest" --> news[(news.json)] --> ns[news_search<br/>document_read]
    pdf[PDF банка — сканы] -- "pnpm ingest" --> png[PNG страниц] -- "pnpm bank:ocr<br/>(Qwen3.6)" --> ocr[(OCR-текст)] -- "pnpm ingest --bank" --> chunks[(фрагменты<br/>с датой и страницей)] --> bs[bank_search<br/>document_read<br/>evidence_verify]
```

Код: `src/tools` — инструменты, `src/agent` — граф, промпты, разбор ответа и поиск источников, `src/news` — разметка и отбор новостей, `src/data` — загрузка данных, `src/search` — BM25, `src/cli` — скрипты.

## Разбор ответа агента

В режиме ленты агент пишет размеченный текст: блок на событие со строками «Тип», «Главное», «Факт», «Позиция банка», «Вывод», «Риск», «Возможность», «Стоит проверить», а в режиме вопроса — «Ответ». `parseFeedAnswer` (`src/agent/feed-parser.ts`) превращает его в JSON без вызова модели:

- факты и позиция банка — дословные цитаты, сверенные `evidenceVerify`; длиннее 300 символов — сокращаются по границе предложения;
- выводы с признаками компании и оговоркой — утверждения `ai_inference`; признаки вне списка бэкенда убираются;
- `summary`, `kind`, `risks`, `opportunities`, `actions`, `answer` — отдельные поля карточки;
- события с пометкой «пропустить» и события не из выбранных сервером в результат не попадают.

`createFeedFinalizer` — готовая функция для опции `finalize` графа: возвращает JSON в формате `batchDraftSchema` бэкенда (лишние поля zod отбросит), а если в ответе нет ни одного блока — вызывает переданный запасной `finalize`. Проверено на ответах 17 живых запусков: все разобранные утверждения прошли `gateDraft` бэкенда.

## Отбор новостей

Два шага:

1. **Разметка** (`pnpm news:tag`, `src/news/tagging.ts`). Модель (`LLM_MODEL_TAGGER`, по умолчанию DeepSeek-V4.1-Flash) пачками по 20 новостей проставляет: группы ОКВЭД вида `46.7` (словарь строится из данных компаний), темы (`key_rate`, `credit`, `fx`, `trade`, `commodities`, `demand`, `labor`, `regulation`, `inflation`), масштаб (`macro`, `sector`, `company`, `other`) и важность 0–3. Ответ проверяется zod, результат кэшируется в `data/processed/news-tags.json`; повторный запуск размечает только новые новости, смена `NEWS_TAG_PROMPT_VERSION` — весь корпус. 1019 новостей ≈ 4,4 ₽.
2. **Отбор** (`rankNewsForCompany`, `src/news/ranking.ts`). Связи компании: своя группа ОКВЭД (0,7; совпадение только по разделу — 0,4), отрасли группы и надёжные отрасли контрагентов с долей от 10%, продукты банка ↔ темы ставки и заимствований, ВЭД ↔ курс и торговля, зарплатный проект ↔ рынок труда. Темы учитываются только для новостей всей экономики или отраслей, связанных с компанией. Вклады объединяются как 1 − ∏(1 − вес), поэтому балл не упирается в 1.

```text
score = 0,65 × companyFit × важность + 0,15 × ракурс + 0,15 × свежесть + 0,05 × источник
важность: 1 → 0,5; 2 → 0,8; 3 → 1      ракурс: CFO — ставка, кредит, курс, инфляция; CEO — спрос, торговля, сырьё, труд, регулирование
свежесть = exp(−возраст / 14 дней), старше 90 дней — исключается
```

Новости «не про бизнес» и с важностью 0 не участвуют; из почти одинаковых заголовков остается более свежий. Результат совместим с `RankedNews` бэкенда, причины — те же ID признаков, что в профиле.

Ограничения: веса подобраны вручную на 6 компаниях, без размеченного тестового набора; группа ОКВЭД 46.7 объединяет топливо и стройматериалы, поэтому топливному оптовику может попасть новость о жилищном строительстве.

## Запуск

**при первой настройке**:

```sh
pnpm install
cp .env.example .env         # вписать LLM_BASE_URL и LLM_API_KEY; ID моделей уже подставлены
pnpm ingest                  # скачивает новости (RSS), вынимает из PDF картинки страниц
pnpm bank:ocr                # распознаёт картинки в текст: ~8 ₽, ~20 мин, повторный запуск продолжает с места обрыва
pnpm ingest --bank           # режет распознанный текст на фрагменты для поиска
pnpm news:tag                # размечает новости для отбора: ~4,4 ₽ на 1019 новостей, лимит --max-rub=10
```

**время от времени:**

```sh
pnpm ingest --news && pnpm news:tag   # свежие новости и их разметка: размечаются только новые
pnpm bank:ocr && pnpm ingest --bank   # только если появились новые PDF банка
```

**задать вопрос агенту:**

```sh
pnpm agent <companyId> "<вопрос>" [modelId]   # 0,2–0,5 ₽;
```

**проверки:**

```sh
pnpm test                                        # после изменений в коде;
pnpm tools:demo [companyId] [запрос]             # что видят инструменты;
pnpm llm:smoke <modelId> ...                     # отвечает ли модель, вызывает ли инструменты, держит ли JSON
pnpm ocr:compare <docId>/p01.png <modelId> ...   # сравнить OCR на одной странице; ~0,15 ₽ за модель
pnpm agent:compare <modelId> ...                 # сравнить модели агента на 5 вопросах; ~4–5 ₽
pnpm news:rank [дата|-] [companyId ...]          # топ-3 отбора новостей для CFO и CEO; бесплатно
```

Результаты проверок — в `results/`. Ответы агента — в `data/processed/runs/`, вне git: в них цитаты материалов банка.

## Модели

Роли: **агент — DeepSeek-V4.1-Flash, OCR — Qwen3.6**. ID берутся из `GET /models` шлюза; используются только модели из списка кейса (PDF, с. 18).

| Модель (ID) | Роль | Сильные стороны | Слабые стороны |
| --- | --- | --- | --- |
| DeepSeek-V4.1-Flash (`deepseek/deepseek-v4.1-flash`) | **Агент** | Сам завершает работу; вызывает несколько инструментов за шаг; использует контрагентов и группу компании; берёт свежий прогноз банка и отмечает, что он менялся; цитаты совпадают с текстом; дешевле Qwen на агентных прогонах | В OCR исказил число на графике (0,09 вместо −0,07); иногда приводит общую причину без опоры на данные |
| Qwen3.6 35B A3B (`qwen/qwen3.6-35b-a3b`) | **OCR** | Без ошибок в числах на 4 страницах (текст, графики, таблица, слайд); принимает изображения, хотя заявлена как текстовая | Как агент: добавляет несуществующие факты о компании, берёт устаревший прогноз банка, пропускает поиск по банку, повторяет одинаковые запросы, чаще упирается в лимит шагов |
| Qwen3-VL-30B-A3B-Instruct (`qwen/qwen3-vl-30b-a3b-instruct`) | Не используется | — | Худший OCR: потерянные минусы, перепутанный порядок значений, выброшенные легенды, **дописанный текст, которого нет на странице**; самая медленная (60–70 с на страницу) |
| Gemma 4 26B A4B (`google/gemma-4-26b-a4b-it`) | — | По кейсу: классификация и извлечение — кандидат для разметки новостей | Не проверялась |
| GLM-5.3-Flash (`z-ai/glm-5.3-flash`) | — | По кейсу: сложный анализ — кандидат для проверки ответов | Не проверялась |
| Kimi-K2.6 (`moonshotai/kimi-k2.6`) | — | По кейсу: текстовая аналитика | Не проверялась |

Сравнения: OCR — [results/ocr-compare-2026-10-21/SUMMARY.md](results/ocr-compare-2026-10-21/SUMMARY.md), базовые возможности — [results/llm-smoke-2026-10-21.md](results/llm-smoke-2026-10-21.md), агент — `pnpm agent:compare`.

`LLM_REASONING_EFFORT=none`: Qwen3.6 и DeepSeek по умолчанию «думают», с рассуждениями ответ пустой, а вызов дороже в 200–300 раз. Стоимость каждого вызова приходит в `usage.cost`; лимит ключа — 500 ₽ в сутки, сброс в 03:00 МСК.

## Данные:

- PDF банка — сканы, текст получен OCR. Из графиков извлекаются только подписанные значения.
- Прогнозы банка менялись: ставка на конец 2026 г. — 13,5% в июле, 14,0% с 11 сентября.
- Отчёт о стали 2021 г. не из списка кейса, помечен как устаревший.
- Компании: 85 525 строк, 85 514 ID (U_428697 ×12 — артефакт обезличивания). Действующих клиентов (CLIENT) — 41 968 ID; Prospect и Close Client остаются только как контрагенты, агент для них не запускается.
- Выручка — за 2025 год, в рублях; значение 1000 — заглушка (599 строк), считается отсутствующим.
- Масштаб оценивается по известной суммарной выручке группы. Это оценка, не сегмент банка: группы выше 15 млрд встречаются и в среднем бизнесе; неизвестная выручка части участников занижает сумму. Выше 15 млрд по одной компании — 115 юрлиц, по группе — 13 601 клиент.
- Платежи: есть самоплатежи (исключаются); у крупных компаний большая часть контрагентов без профиля.
- Продукты в профиле — только Альфа-Банка.
- RSS даёт в основном заголовок и лид, полный текст только у РБК.
