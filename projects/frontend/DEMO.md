# Демонстрация полного продуктового цикла

Ветка `codex/mock-app-cycle` основана на `codex/alfa-shadcn-theme`. Главная страница теперь запускает интерактивное приложение на моках; `/ui-kit` остаётся доступной.

## Запуск

Node 24.19.0, pnpm 11.25.0, `pnpm install --frozen-lockfile`, затем `pnpm --filter @alfa/frontend dev`. Открыть http://localhost:3000. Backend, PostgreSQL, SSO и LLM не нужны. Сборка: `pnpm --filter @alfa/frontend build`.

## Сценарий проверки

1. На стартовом экране открыть аналитику, выбрать «Север Металл» и финансового директора.
2. Лента показывает шесть событий. Первым будет событие о ставке; причина релевантности связана с кредитной нагрузкой.
3. Открыть разбор: факт, влияние на компанию, риск, возможность, следующий шаг, учебная аналитика и пробелы данных. Вкладки «Источники» и «Как получен вывод» объясняют происхождение вывода.
4. Спросить «Какие риски?» или «Что сделать?». Сценарный ответ учитывает текущую компанию и роль. Произвольный неподдержанный вопрос получает честное ограничение вместо выдуманного ответа.
5. Сохранить событие, поставить оценку/замечание, закрыть разбор. Проверить «Сохранённое» и перезагрузить страницу: состояние остаётся.
6. Через переключатель компании выбрать «Город Маркет»: первым станет событие о собственных торговых марках. Избранное, диалоги и feedback из другой компании/роли не отображаются. Для «Север Металл» смена CFO на генерального директора меняет первый приоритет со ставки на энергию.
7. Проверить поиск, фильтры и скачивание текстовой сводки; экспорт содержит текущий отфильтрованный набор и маркировку демо.
8. Обновить анализ: четыре этапа, затем запись в истории. Отменить следующий запуск — история фиксирует отмену, результат отменённого анализа не публикуется.
9. Через «Сценарии демо» проверить частичный результат, пустой результат, ошибку, лимит и отказ в доступе. Кнопка повторного запуска возвращает обычный сценарий.
10. Проверить профиль компании, пропуски данных, светлую/тёмную тему. «Сбросить мои демо-данные» очищает только данные этого приложения и возвращает на старт.

## Архитектура и границы

- `src/features/demo/model.ts` — типизированные синтетические fixtures, объяснимое ранжирование, сценарный асинхронный анализ с AbortSignal, ограниченный чат.
- `session.ts` — валидируемое Zod состояние в localStorage (`alfa-demo-v1`), восстановление после reload, безопасный fallback при повреждении/недоступности хранилища.
- `app.tsx` — входная точка, выбор контекста, лента, профиль, избранное, история, экспорт и управление сценариями.
- `insight-detail.tsx` — разбор, встроенные учебные документы, трасса, вопросы и feedback.
- UI строится на локальном shadcn/ui и токенах темы из PDF. Все компоненты установлены, импортируются только используемые.

Это функциональный frontend-прототип, не реализация серверных контрактов из `specs/05-api-and-ui.md`. Нет банковской авторизации, реального получения новостей, API, SSE, RAG, LLM, фонового воркера, юридических/финансовых действий и отправки feedback в банк. Трасса — симуляция, документы и позиции явно помечены как учебные. Историческая дата набора — 21 октября 2026, а время запусков показывается фактическое в МСК.

Данные сохраняются только в текущем браузере. Company/role scope — UX-изоляция моков, не security boundary. Не вводите реальные клиентские данные в демо. История ограничена 50 запусками, диалог — 20 парами сообщений на инсайт. При закрытии разбора незавершённый ответ отменяется.

Проверки: `pnpm --filter @alfa/frontend test`, `pnpm --filter @alfa/frontend typecheck`, `pnpm --filter @alfa/frontend build`. Unit-тесты проверяют персонализацию, область контекста, отказ от неподдержанного ответа, успех/ошибку/частичный/пустой результат и отмену.
